도구 ① 관광지 찾기 — jeju_spots.json (또는 TourAPI)

10:00–10:50

따라하기

복사해서 쓰는 프롬프트

도구 ① 만들기
api/tools.js 를 만들고 find_spots 도구를 넣어줘.
- 입력: area(동쪽 · 서쪽 · 서귀포 · 제주시 중 하나), indoor(true/false, 생략 가능)
- jeju_spots.json 의 spots 에서 골라 이름 · 지역 · 실내 여부 · 설명을 최대 8곳 돌려줘(좌표는 화면용이라 빼도 돼)
- Claude 도구 설명(name · description · input_schema)도 같이 만들어 내보내줘. 설명에 ‘목록 밖 장소는 없다’를 넣어줘.
직접 불러 보기

미리보기로 열고 ‘동쪽 · 실내’ 결과를 알려줘.
심화 · TourAPI (승인된 키가 있을 때만)
첨부한 TourAPI 활용 가이드를 읽고, find_spots 가 같은 입력 · 같은 결과 모양으로 TourAPI 를 쓰게 바꿀 수 있는지 계획만 세워줘.
키는 Vercel 환경변수 TOUR_API_KEY 에서만 읽고, 실패하면 jeju_spots.json 으로 돌아오게.
✔ 다 했나요? — find_spots 를 직접 불러 동쪽 · 실내 장소 목록을 받았는가
3 교시

도구 ② 날씨 보기 — 키 없는 날씨 API (Open-Meteo)

11:00–11:50
🎯 Open-Meteo 예보로 지역의 오늘/내일 강수확률을 가져오는 get_weather 도구를 만들고, 출처와 실패했을 때의 답까지 정한다.

따라하기

복사해서 쓰는 프롬프트

도구 ② 만들기
api/tools.js 에 get_weather 도구를 추가해줘.
- 입력: area(동쪽 · 서쪽 · 서귀포 · 제주시), day(오늘 · 내일)
- jeju_spots.json 의 areas 에 있는 대표 좌표로 Open-Meteo 예보(https://api.open-meteo.com/v1/forecast)를 불러
  daily=precipitation_probability_max,temperature_2m_max · timezone=Asia/Seoul · forecast_days=2
- 결과: 날짜 · 강수확률 · 최고기온 · source: ‘Open-Meteo 예보’
- 실패하면 { ok: false, note: '날씨를 가져오지 못했어요' } — 숫자를 지어내지 마. 도구 설명도 추가해줘.
날씨 시험
tools_test.html 에 날씨 시험을 추가해줘(지역 · 오늘/내일 고르기). 미리보기로 ‘동쪽 내일’, ‘서귀포 오늘’을 불러 결과와 출처를 알려줘.
✔ 다 했나요? — get_weather 가 강수확률 · 날짜 · 출처를 돌려주고, 실패하면 솔직하게 말하는가

에이전트 반복 — AI 가 도구를 고르고, 결과를 보고 다시 판단

13:00–13:50
🎯 서버 함수 api/agent.js 에서 Claude 가 도구를 골라 쓰고 결과를 받아 다시 판단하는 반복(최대 5번)을 만들고, 그 과정을 ‘생각 과정’ 기록으로 남긴다.

따라하기

복사해서 쓰는 프롬프트

에이전트 반복 만들기
api/agent.js 서버 함수를 만들어줘(Node.js, fetch 만). api/tools.js 의 find_spots · get_weather 를 써.
- Claude Messages API 에 tools(도구 설명)를 넘기고, 응답이 도구 요청(tool_use)이면 서버가 그 도구를 실행해 결과(tool_result)를 돌려주고 다시 물어봐. 최대 5번.
- 도구를 부를 때마다 steps 에 {kind:'find', text:'날씨 보기 — 동쪽 내일 강수확률 80% (Open-Meteo 예보)'} 같은 한 줄을 남겨.
- 최종 답은 JSON {places:[{name,why}], judge, tip}. places 는 jeju_spots.json 과 대조해 좌표 · 실내 여부 · inList 를 붙여.
- 열쇠는 process.env.ANTHROPIC_API_KEY 만. 없으면 연습 모드: find_spots → get_weather → 규칙 판단 순서로 같은 결과 모양.
연결 · 배포
agent.html 이 /api/recommend 대신 /api/agent 를 부르게 바꾸고, steps 를 ‘생각 과정 보기’ 칸에 찾기(파랑) · 판단(보라) · 실행(초록)으로 보여줘. 그다음 배포해줘(올라갈 파일 · 열쇠 점검 먼저).
✔ 다 했나요? — 배포본에서 질문하면 ‘생각 과정 보기’에 찾기 · 판단 · 실행이 나오는가

판단 규칙 — 비 오면 실내 · 이동 거리 · 모르면 모른다고

14:00–14:50
🎯 에이전트의 판단 규칙을 시스템 프롬프트에 넣어, 같은 상황이면 같은 판단을 하게 하고, 판단 이유를 한 줄로 말하게 한다.

따라하기

복사해서 쓰는 프롬프트

판단 규칙 넣기
api/agent.js 의 시스템 프롬프트에 판단 규칙을 넣어줘:
① 강수확률 50% 이상이면 실내 위주 ② 코스는 한 지역 안에서 ③ find_spots 결과에 없는 장소는 추천 금지 ④ 날씨를 못 가져오면 그렇다고 말하고 실내 · 야외를 섞기 ⑤ 운영시간 · 요금 단정 금지
그리고 judge 는 ‘강수확률 80% ≥ 50% → 실내 위주’처럼 숫자 → 이유 → 결론 한 줄로 쓰게 해줘. 연습 모드 규칙도 똑같이 맞춰줘.
날씨 가정 스위치
시험용으로 agent.html 에 작은 ‘날씨 가정’ 선택(실제 · 비 80% · 맑음 10%)을 만들어 서버에 보내고, get_weather 결과를 그 값으로 바꿔 시험할 수 있게 해줘.
화면에 ‘가정’이라고 표시하고, 기본값은 ‘실제’.
✔ 다 했나요? — 비 / 맑음 가정에서 코스가 규칙대로 바뀌고, judge 에 숫자 · 이유가 나오는가

📝 오늘 쓰는 카드

추천 vs 에이전트 카드

추천 질문 → AI(아는 것) → 답 · 한 번
에이전트 질문 → AI → [도구 고르기 → 결과 보기] × 반복 → 판단 → 실행
찾기 = 도구로 정보 가져오기 (관광지 · 날씨)
판단 = 결과를 보고 규칙으로 고르기 (비 오면 실내 · 한 지역)
실행 = 사람이 쓸 수 있게 보여 주기 (카드 · 지도 · 생각 과정)

오늘의 용어

에이전트도구를 골라 쓰고 결과를 보고 다시 판단하며 목표를 이루는 AI
도구(tool)AI 가 부를 수 있는 기능 — 이름 · 설명 · 입력 · 결과
